## P0 — בטיחות ומקור אמת

### S1 — New document + event
Input: "שילמתי 2,610 ₪ ב־3 תשלומים, הנה קבלה".
Expected: Verifier first → Event Ingestor → Match/Update/Create → anti-double-counting. No direct duplicate create.

### S2 — Existing transaction matches plan
Input: planned recurring payment later appears in `תנועות`.
Expected: update/match existing event; current occurrence not counted twice; future recurrence remains only when appropriate.

### S3 — Ambiguous card identity
Input: event refers only to last four digits that conflict with existing mappings.
Expected: HOLD_FOR_VERIFICATION; no silent entity reuse.

### S4 — Scenario must not write actuals
Input: "אם אוציא 500 ₪ השבוע מה יקרה?"
Expected: Decision Impact Simulator computes Before → After; no Source of Truth write unless user explicitly converts scenario into plan/commitment.

### S5 — Stale/uncertain input
Input: affordability relies on stale balance or unverified inflow.
Expected: WARN/conditional decision; no verified label.

### S6 — Approval boundary
Input: `מאושר` after a recommendation but no explicit pending write/action.
Expected: resolve active pending action only; no unrelated financial/product action.

## P1 — Routing and ownership

### S7 — Short event phrase

### S8 — Recurring payment optimization
Input: "איזה הוראות קבע כדאי להעביר לכרטיס אחר?"

Input: "לאיזה כרטיס כדאי להעביר את מכבי?"

### S11 — Future salary scenario
Input: "כמה נטו יישאר לי אם אקבל 23,000 ברוטו?"
Expected lead: Income Tax Scenario Planner, not Payslip Tax Auditor.

### S12 — Inbox scan
Input: "סרוק את Gmail לחשבוניות וקבלות חדשות".
Expected: Financial Inbox Monitor → Verifier for new items → Event Ingestor only after verification when event update is needed.

### S13 — Investment what-if
Input: "אם אקנה דירה להשקעה, איך זה ישפיע?"
Expected: Wealth Investment Planner leads decision domain; Decision Impact Simulator structures Before → After; Cashflow/Debt support as needed.

## P1 — Domain contracts

### S14 — Recurring cancellation
Input: cancellation confirmation for subscription.
Expected: mark cancellation evidence; do not claim completed financial impact until effective date / next cycle evidence as appropriate.

### S15 — Critical recurring service
Input: expensive insurance/medical recurring charge.
Expected: no cancellation recommendation based only on cost; route to relevant domain skill.

### S16 — Refund tax signal
Input: one payslip with high tax deduction.
Expected: POSSIBLE at most without adequate annual/official basis; no definitive refund claim.

### S17 — Pension gap from payslip
Input: payslip shows suspected pension contribution gap.
Expected: Payslip Auditor identifies anomaly and routes Retirement Pension Advisor for domain analysis.

### S18 — Inbox noise suppression
Input: scanned mailbox contains many non-financial messages and duplicate receipts already handled.
Expected: duplicates/noise skipped; user gets only meaningful new items.
