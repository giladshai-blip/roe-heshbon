# Financial Skill Router

## מטרה
לזהות את סוג הבקשה ולהפעיל את ה־Skill המתאים בלי לערבב תחומי אחריות ובלי לעקוף את ההנחיה המרכזית.

## כלל עליון
לפני ניתוח פיננסי משמעותי, שינוי מערכת, קוד, דשבורד, נוסחה, תחזית, KPI, סנכרון, אימות נתונים או החלטה פיננסית — קרא את `docs/project-instructions.md` מתוך branch `main`.

## כלל קדימות למסמך חדש
כאשר בקשה כוללת מסמך, צילום, דוח, אישור, הודעת בנק, הודעת חיוב או ראיה פיננסית חדשה — תמיד התחל ב־`financial-document-verifier`, גם אם המשתמש מבקש באותה הודעה גם החלטה על תזרים, אשראי, תקציב, חוב, זכויות, שכר, השקעה או פנסיה.

סדר הפעולה המחייב:
1. אמת וסווג את המסמך.
2. קבע אילו נתונים הוא מאמת, מעדכן, משלים, סותר או משאיר כ־`דורש אימות`.
3. בצע Match → Update → Create ו־anti-double-counting.
4. רק לאחר מכן העבר את הנתונים המאומתים ל־Skill התומך הנדרש לקבלת ההחלטה.
5. אם האימות לא הושלם או קיימת סתירה מהותית — אל תבסס החלטה סופית על הנתון השנוי במחלוקת.

דוגמה: "העברתי הוראת קבע לספק רפואי לכרטיס A — איך זה משפיע על התזרים?" → קודם `financial-document-verifier`, אחר כך `credit-card-optimizer` ו־`cashflow-guardian` לפי הצורך.

## ניתוב
- מסמך, צילום, דוח, אישור או הודעת חיוב חדשה → `financial-document-verifier`.
- מצב תזרים, יתרת עו״ש, 30 יום, מינוס, יכולת לבצע רכישה/חופשה או תרחיש תזרימי קרוב → `cashflow-guardian`.
- בחירת כרטיס, מעבר הוראת קבע, מסגרת אשראי, מועד חיוב או פיזור עומס → `credit-card-optimizer`.
- תקציב, קטגוריות, חריגות, תכנון חודשי או הקצאת כסף → `budget-planner`.
- כיול תחזית, baseline צריכה, עונתיות, חגים, שינוי התנהגות צרכנית או השוואת תחזית מול ביצוע → `forecast-calibration-analyst`.
- שכר ברוטו/נטו, הצעת עבודה, שינוי שכר, רכב/אחזקת רכב, נקודות זיכוי, הכנסה עתידית או כניסת בן/בת זוג לעבודה → `income-tax-scenario-planner`.
- הלוואה, מינוס, חוב, מחזור, פירעון מוקדם, סדר עדיפות לסגירת חובות או הלוואה חדשה → `debt-loan-strategist`.
- דירוג אשראי, פרופיל אשראי, החזרות, פיגורים, ניצול מסגרות כולל, יעד ציון או פתיחת אשראי חדש → `credit-profile-optimizer`.
- זכויות, הטבות, מענקים, הנחות, קצבאות, הטבות מס או זכאות מוסדית/ממשלתית → `benefits-rights-finder`.
- חיסכון, השקעה, נדל״ן להשקעה, הקצאת הון, נזילות, הון נטו או בניית הון ל־5 שנים → `wealth-investment-planner`.
- פנסיה, גמל, השתלמות, כיסויים, דמי ניהול, מסלולים או פרישה → `retirement-pension-advisor`.
- תקלה, סנכרון, כפילות, נוסחה, דשבורד, KPI, איכות נתונים או בריאות מערכת → `financial-system-auditor`.

## בקשה משולבת
כאשר בקשה נוגעת ליותר מתחום אחד:
1. אם קיים מסמך חדש — כלל קדימות למסמך חדש גובר על כל כלל ניתוב אחר.
2. אחרת, בחר Skill מוביל לפי ההחלטה שהמשתמש מבקש לקבל.
3. הפעל Skills תומכים רק לחלקים הנדרשים.
4. אל תחשב אותו אירוע כלכלי ביותר מ־Skill אחד ללא התאמה מפורשת.
5. בצע anti-double-counting לפני מסקנה סופית.

דוגמאות:
- "האם כדאי למחזר הלוואה כדי לצאת מהמינוס?" → `debt-loan-strategist` מוביל, `cashflow-guardian` תומך.
- "איזה מענקים מגיעים לנו ואיך הם ישפיעו על התקציב?" → `benefits-rights-finder` מוביל, `budget-planner` תומך; הטבה לא מאושרת תישאר תרחיש בלבד.
- "אחרי החגים ההוצאות צפויות לרדת — איך לעדכן את התחזית?" → `forecast-calibration-analyst` מוביל, `cashflow-guardian` תומך; הירידה נשארת הנחה עד אימות בביצוע.
- "האם שכר חדש יספיק כדי לצאת מהמינוס?" → `income-tax-scenario-planner` מוביל, `cashflow-guardian` תומך.
- "איך לשפר את פרופיל האשראי בלי לפגוע בתזרים?" → `credit-profile-optimizer` מוביל, `credit-card-optimizer` ו־`cashflow-guardian` תומכים לפי הצורך.
- "האם נכון להשקיע בנכס עכשיו?" → `wealth-investment-planner` מוביל, `cashflow-guardian` ו־`debt-loan-strategist` תומכים.

## סדר עדיפות נתונים
1. נתון חדש בשיחה הנוכחית.
2. נתון מאומת ועדכני בקובץ `רואה חשבון - מערכת פיננסית`.
3. מסמך רשמי או מקור מחובר ועדכני.
4. נתון מאומת קודם.
5. נתון מחושב.
6. תחזית או הנחה.

## תנאי עצירה
עצור וסמן `דורש אימות` אם קיימת סתירה מהותית בזהות חשבון/כרטיס, סכום, תאריך, בעלים, תנאי הלוואה, תנאי זכאות, נתוני מס, מקור דירוג אשראי, תנאי השקעה או מקור נתון שעלולה לשנות החלטה.

אם חסר נתון מהותי, אין להשלים אותו בניחוש. מותר לבצע תרחיש רק אם הוא מסומן במפורש כ־`הנחה` או `תרחיש` ואינו מוצג כמצב בפועל.

## חוזה תוצאה אחיד
כל Skill מחזיר לרכיב המנתב סטטוס עבודה בפורמט הבא:
- `status`: `PASS` | `WARN` | `FAIL`
- `data_state`: `מאומת` | `מחושב` | `תחזית` | `הנחה` | `דורש אימות` | שילוב שלהם
- `source`: מקור הנתון המרכזי ששימש להחלטה
- `impact`: התחומים שנבדקו או הושפעו
- `decision`: המסקנה או הפעולה המומלצת
- `next_check`: מה נדרש לאמת או לבדוק בהמשך

משמעות הסטטוסים:
- `PASS` — יש בסיס נתונים מספיק וההחלטה עקבית עם ההנחיה.
- `WARN` — ניתן לתת תשובה חלקית/מותנית, אך יש נתון חסר, ישן או לא סגור.
- `FAIL` — אין בסיס בטוח להחלטה או קיימת סתירה מהותית.

## פלט
החזר תשובה אחת מאוחדת. אין צורך לחשוף למשתמש את שמות ה־Skills או את אובייקט הסטטוס הפנימי אלא אם הוא שואל כיצד המערכת פעלה. כן יש לחשוף למשתמש חוסר ודאות מהותי, סתירה או תנאי שמשנה את ההמלצה.
