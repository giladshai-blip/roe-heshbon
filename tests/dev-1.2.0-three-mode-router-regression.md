# Regression — dev-1.2.0 Three-Mode Conversation Router

מטרה: לוודא שכל שיחה חדשה מנותבת לאחד משלושה מצבים בלבד: גבי / DEV / CORE.

## Acceptance tests

1. **פתיחה כללית**
   - קלט: `היי`
   - צפוי: מוצגות בדיוק 3 אפשרויות: גבי / DEV / CORE.
   - אין טעינת נתונים פיננסיים לצורך התפריט.

2. **בחירה 1**
   - קלט: `1`
   - צפוי: `conversation_mode=GABI_AGENT`.
   - גבי מופעל מיד; אין צורך לכתוב אחר כך `היי גבי`.

3. **בחירה 2**
   - קלט: `2`
   - צפוי: `conversation_mode=DEV_ENVIRONMENT`.
   - כל פעולת GitHub פיתוח מכוונת ל־`dev` כברירת מחדל.

4. **בחירה 3**
   - קלט: `3`
   - צפוי: `conversation_mode=CORE_RUNTIME`.
   - מקור הקוד/ההנחיה הוא `main`; אין שינוי ניסויי ישיר ב־main.

5. **קיצור ישיר — גבי**
   - קלט ראשון: `היי גבי`
   - צפוי: מעבר ישיר ל־GABI_AGENT בלי להציג תפריט קודם.

6. **קיצור ישיר — DEV**
   - קלט ראשון: `היי dev`
   - צפוי: מעבר ישיר ל־DEV_ENVIRONMENT בלי להציג תפריט קודם.

7. **קיצור ישיר — CORE**
   - קלט ראשון: `היי core`
   - צפוי: מעבר ישיר ל־CORE_RUNTIME בלי להציג תפריט קודם.

8. **המשך שיחה**
   - לאחר בחירת מצב, הודעות נוספות נשארות באותו מצב בלי לשאול שוב בכל הודעה.
   - התפריט מוצג מחדש רק בשיחה חדשה או לאחר פקודת החלפת מצב.

9. **החלף מצב**
   - קלט: `החלף מצב`
   - צפוי: חזרה ל־UNSET והצגת שלוש האפשרויות.

10. **תפריט**
    - קלט: `תפריט`
    - צפוי: שלוש האפשרויות מוצגות שוב; אין אובדן היסטוריית השיחה.

11. **DEV isolation**
    - במצב DEV שינוי ניסויי נכתב ל־`dev` בלבד.
    - `main` לא משתנה במהלך ניסוי.

12. **CORE safety**
    - במצב CORE ניתן לבדוק את המערכת הפעילה ולבצע פעולות תפעול מאושרות.
    - בקשת פיתוח חדשה אינה נכתבת ישירות ל־main; יש להעבירה ל־DEV / מסלול קידום.

13. **Gabi startup**
    - במצב GABI_AGENT, לפני מספר פיננסי מהותי נבדקים מקור אמת ו־Freshness לפי הכללים הקיימים.

## FAIL
- מוצגות אפשרויות ישנות: תפעול מערכת / תזרים / הון אישי.
- בחירת מספר דורשת אחריה טריגר נוסף.
- `היי dev` מפעיל את גבי.
- `היי core` מכוון ל־dev.
- DEV משנה main ישירות.
- CORE משמש סביבת ניסוי לא בדוקה.

## Promotion gate
כל הבדיקות לעיל חייבות לעבור לפני קידום `dev-1.2.0` ל־`core-1.2.0`.
