# גבי — היסטוריית גרסאות

קובץ זה הוא יומן הגרסאות הקנוני של הסוכן **גבי** בפרויקט `רואה חשבון`.

## כללי גרסאות

- **Agent Version** מתאר את גרסת ההתנהגות, ההנחיות, היכולות והאורקסטרציה של גבי בריפו.
- **Runtime Model** מתאר את מודל ChatGPT שמריץ את הסוכן בזמן השיחה. הוא אינו מחליף את מספר גרסת הסוכן ועלול להשתנות בנפרד.
- שינוי התנהגות/יכולת של גבי מחייב עדכון גרסה ותיעוד כאן.
- שינוי בפיתוח מתחיל ב־`dev` או בענף פיתוח ייעודי מבוסס `main` כאשר `dev` אינו מסונכרן; `main` נשאר קו יציב.
- בכל גרסה יתועדו לפחות: תאריך, מטרה, שינויים, קבצים שהושפעו, בדיקות שבוצעו ומגבלות ידועות.
- אין לשמור בקובץ זה סודות, tokens, סיסמאות או נתונים פיננסיים אישיים רגישים.

## 0.6.0-dev — Personal Learning Layer

**תאריך התחלה:** 2026-09-14  
**סטטוס:** Development  
**Branch:** `dev-gabi-0.6-learning`  
**Base:** `0.5.0` מ־`main`

### מטרה
להפוך את גבי לסוכן אישי לומד שמסתגל באופן מתמשך לגלעד, תוך שמירה על מקור אמת פיננסי, גבולות הרשאה ואימות.

### נוסף בפועל
- מנגנון למידה: `Observe → Candidate → Evidence → Confidence → Apply → Validate → Promote`.
- Context First לפני שאלת הבהרה.
- Intent Compression לפקודות קצרות כגון `תזרים`, `מה חדש`, `תבדוק`, `תתקן`, `מאושר`.
- Response Adaptation לברירת מחדל קצרה, ישירה ומעשית.
- Action Bias לפעולות בטוחות והפיכות במסגרת הרשאות קיימות.
- Friction Learning לזיהוי תיקונים חוזרים והפיכתם ל־System Improvement Candidate.
- Memory Boundary שמונע מזיכרון אישי להחליף מקור אמת פיננסי.
- KPI למדידת חיכוך: בקשות מידע חוזרות, שיעור תיקונים, צעדים לתוצאה, השלמת פעולות, רעש ושימור דפוסים.
- Registry ראשון של דפוסים מוכחים ב־`LEARNED-PATTERNS.md`.
- חבילת Regression בת 12 תרחישים.

### קבצים
- `agents/family-cfo-agent/versions/0.6.0-dev.md`
- `agents/family-cfo-agent/LEARNED-PATTERNS.md`
- `agents/family-cfo-agent/tests/0.6-learning-regression.md`
- `agents/family-cfo-agent/CHANGELOG.md`

### החלטת ארכיטקטורה
בשלב הפיתוח 0.6 מוגדר כ־Overlay מעל `AGENT.md@0.5.0`. כך ניתן לבדוק את ההתנהגות החדשה בלי לדרוס את קובץ הסוכן היציב. לאחר מעבר Regression מוצלח, הכללים יאוחדו לקובץ הקנוני `AGENT.md` לפני קידום ל־`main`.

### בדיקות
- נכתבו 12 תרחישי Regression המכסים: הוראה מפורשת, אירוע חד־פעמי, Context First, גבול מקור אמת, Intent `מה חדש`, גבול `מאושר`, Action Bias, פעולה בלתי הפיכה, Friction חוזר, תשובה קצרה, סתירה מול העדפה ולמידה מתמשכת.
- טרם בוצעה הרצת Runtime מלאה; הגרסה אינה מוכנה ל־main בשלב זה.

### נדרש בהמשך
- להריץ את ה־Regression הלוגי בפועל.
- לבדוק שילוב עם Router/Skills קיימים.
- לאחד את Overlay ל־`AGENT.md` לאחר הצלחה.
- לבדוק האם נדרש להעלות כלל למידה רוחבי גם ל־`docs/project-instructions.md`.

## 0.5.0 — Baseline

**תאריך בסיס:** 2026-09-14  
**סטטוס:** Stable / `main`  
**שם הסוכן בשיחה:** גבי  
**Agent ID:** `family-cfo-agent`  
**Runtime Model בעת קביעת הבסיס:** `GPT-5.6 Sol`

### תפקיד
גבי הוא הסוכן הפיננסי הראשי של פרויקט `רואה חשבון` ומשמש שכבת אורקסטרציה לניהול התמונה הפיננסית המשפחתית, ניתוח, תחזיות, אימות מסמכים, סיכונים, המלצות ותפעול מערכת פיננסית בהתאם ל־`docs/project-instructions.md`.

### יכולות בסיס בגרסה 0.5.0
- Always-On Conversation Mode בהקשר פיננסי.
- תמונת מצב ויזואלית בתחילת שיחה פיננסית כאשר הנתונים זמינים.
- שימוש ב־`רואה חשבון - מערכת פיננסית` כמקור האמת המרכזי.
- Match → Update → Create ומניעת ספירה כפולה.
- ניתוח תזרים, 30 יום, תקציב, אשראי, חובות, חיסכון, פנסיה, הון נטו ותוכנית 5 שנים לפי הצורך.
- Proactive Mode לזיהוי סיכונים והזדמנויות בכל הרצה רלוונטית.
- Level 2 Operational Autonomy לשינויים בטוחים, הפיכים ומוגבלים בהתאם לכללי הסוכן.
- Full Skill Autonomy ליצירה, עדכון, בדיקה וקידום Skills תחת תנאי הבקרה שהוגדרו.
- הפרדה בין נתון מאומת, נתון מחושב, תחזית, הנחה ונתון שדורש רענון.
- עצירת החלטה כאשר חסר מידע מהותי או קיימת סתירה מהותית.

### מקור סמכות
1. `docs/project-instructions.md` ב־`main` — ההנחיה המרכזית והמחייבת.
2. `agents/family-cfo-agent/AGENT.md` — הגדרת הסוכן.
3. Skills / Router / קוד / מקור האמת — בהתאם להיררכיה המוגדרת בהנחיית הפרויקט.

### מצב בדיקה בנקודת הבסיס
- גרסת הסוכן ב־`AGENT.md`: `0.5.0`.
- סטטוס הסוכן: `main`.
- ההנחיה המרכזית מגדירה את `family-cfo-agent` כסוכן ברירת המחדל בפרויקט.
- לא בוצע שינוי לוגי או קוד במסגרת יצירת נקודת הבסיס; זהו תיעוד של המצב הקיים בלבד.

### מגבלות ידועות
- גבי אינו תהליך רקע רציף בפני עצמו; ניטור עתידי מחייב Runtime/Automation מתאים.
- פעולות פיננסיות בלתי הפיכות ושינויי קוד אפליקטיביים מהותיים נשארים כפופים לכללי האישור וה־`dev → test → main`.
- גרסת Runtime Model אינה מספר הגרסה של הסוכן ואינה בשליטת הריפו.

## מדיניות התפתחות מכאן

לאחר סיום מוצלח של `0.6.0-dev`, הגרסה תקודם ל־`0.6.0` ב־`main` רק לאחר איחוד הכללים לקובץ הקנוני, בדיקה וקריאה חוזרת.

בכל שדרוג עתידי נרשום כאן:
- **למה שודרג**.
- **מה השתנה בפועל**.
- **איזה קובץ/Skill/כלל השתנה**.
- **איך נבדק**.
- **מה עדיין חסר**.
- **האם נדרש שינוי גם ב־`docs/project-instructions.md`**.

כך ניתן יהיה להשוות כל גרסה של גבי לקודמתה ולשחזר במדויק איך הסוכן התפתח לאורך זמן.
