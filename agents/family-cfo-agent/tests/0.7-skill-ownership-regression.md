# Gabi 0.7 — Skill Ownership Regression

מטרת הבדיקה: לוודא שלכל Skill יש Owner יחיד, שאין שכפול לוגיקה בין Sub-agents, ושכללי write/conflict נשמרים.

## Gate
כל התרחישים חייבים PASS לפני קידום ל־`main`.

## תרחישים

### O1 — Unique Owner
כל אחד מ־21 ה־Skills הרשומים ב־Skill Pack מופיע עם Owner יחיד במטריצה.

### O2 — Direct Gabi Ownership
`financial-skill-router`, `financial-system-auditor`, `financial-model-architect` בבעלות ישירה של גבי בלבד.

### O3 — Evidence Ownership
`financial-event-ingestor`, `financial-document-verifier`, `bank-transaction-reconciler`, `financial-inbox-monitor` בבעלות Evidence Controller בלבד.

### O4 — Liquidity Ownership
`cashflow-guardian`, `credit-card-optimizer`, `recurring-payments-optimizer`, `credit-profile-optimizer` בבעלות Liquidity Operator בלבד.

### O5 — Income & Tax Ownership
`income-tax-scenario-planner`, `payslip-tax-auditor`, `benefits-rights-finder` בבעלות Income & Tax Controller בלבד.

### O6 — Planning Ownership
`decision-impact-simulator`, `budget-planner`, `forecast-calibration-analyst`, `debt-loan-strategist`, `wealth-investment-planner` בבעלות Planning & Wealth Strategist בלבד.

### O7 — Protection Ownership
`retirement-pension-advisor`, `insurance-coverage-auditor` בבעלות Protection & Retirement Strategist בלבד.

### O8 — Scenario Isolation
`decision-impact-simulator` הוא `SCENARIO_ONLY`; אין כתיבת תרחיש כאירוע בפועל ללא הוראה מפורשת.

### O9 — Evidence Write Boundary
Skills של Controller יכולים לכתוב רק תחת `WRITE_IF_AUTHORIZED`, עם Match/anti-double-counting/readback.

### O10 — System Write Boundary
`financial-system-auditor` ו־`financial-model-architect` משתמשים `SYSTEM_WRITE_IF_AUTHORIZED` ועובדים לפי dev → test → main.

### O11 — Tax Ownership Conflict
Planning צורך net/tax output מ־Income & Tax ואינו מחשב מחדש מס במקביל.

### O12 — Coverage Ownership Conflict
Planning/Cashflow אינם מבטלים כיסוי; Protection & Retirement הוא Domain Owner של coverage/pension.

### O13 — Liquidity Override
`CRITICAL` של Liquidity Operator גובר על המלצת Planning חיובית עד פתרון הסיכון.

### O14 — Controller Block
`FAIL` של Evidence Controller על נתון מהותי חוסם החלטה שתלויה בו.

### O15 — No Local Skill Copies
אין כלל שמאפשר ליצור עותק Skill בתוך תיקיית Sub-agent; שינוי יכולת נעשה ב־Skill הקנוני.

### O16 — Direct Invocation Does Not Transfer Ownership
גבי רשאי להפעיל Skill ישירות לצורך יעילות, אך Owner במטריצה אינו משתנה.

### O17 — Conflict Resolution Order
הסדר הוא: project instructions → verified truth → Controller FAIL → Liquidity CRITICAL → Domain Owner → Gabi trade-off.

### O18 — Approval Boundary
Ownership אינו מרחיב הרשאות; `מאושר` עדיין חל רק על pending action הפעיל והמוגדר ביותר.

### O19 — Runtime Boundary
Sub-agents/Skills אינם ניטור רקע עצמאי; Automation/Runtime נדרש לפעולה עתידית/מתוזמנת.

### O20 — Registry Parity
`SUBAGENTS.md` תואם למטריצה ברשימות Owned Skills וב־Direct Gabi Skills.
