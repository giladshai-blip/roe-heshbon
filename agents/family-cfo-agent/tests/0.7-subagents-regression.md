# Gabi 0.7 — Sub-Agent Architecture Regression

**Scope:** rebuilt Sub-agent layer under `family-cfo-agent`.

## Promotion gate
The architecture may be promoted only if all scenarios pass at specification/readback level, no ownership conflict remains, and no Sub-agent can bypass Gabi's approval/source-truth rules.

## Scenarios

### S1 — New receipt + cashflow impact
Input: new receipt and question about cashflow.
Expected: Controller → Cashflow → Gabi. Document/Event Skills run under Controller first.

### S2 — New payslip
Input: new payslip and tax question.
Expected: Controller → Income & Tax → Gabi.

### S3 — Salary offer only
Input: future salary offer, no actual payslip.
Expected: Income & Tax models scenario; must not treat offer as current income.

### S4 — Salary change affects overdraft
Expected: Income & Tax → Cashflow → Planning → Gabi.

### S5 — 500 ₪ what-if
Expected: Planning via Decision Impact; scenario must not be written as actual transaction.

### S6 — Cashflow critical vs positive long-term plan
Expected: Cashflow CRITICAL overrides positive Planning until liquidity risk resolved.

### S7 — Duplicate transaction risk
Expected: Controller owns match/duplicate decision; domain agents do not create second event.

### S8 — Ambiguous card identity
Expected: Controller returns WARN/FAIL; Cashflow cannot silently use ambiguous card mapping.

### S9 — Recurring payment optimization
Expected: Cashflow owns timing/cards/recurring lifecycle; Planning is not required unless long-term impact is material.

### S10 — Insurance cancellation candidate
Expected: Protection & Retirement owns coverage analysis; Planning/Cashflow cannot cancel coverage merely to improve budget.

### S11 — Pension report + payslip discrepancy
Expected: Controller verifies evidence; Income & Tax owns payslip contribution; Protection & Retirement owns pension/coverage implication; Gabi reconciles.

### S12 — Tax refund question from one payslip
Expected: Income & Tax may return signal only; no guaranteed refund without annual/official basis.

### S13 — Investment decision
Expected: Cashflow checks liquidity first; Planning owns investment decision; Protection & Retirement joins only if protection/retirement is materially affected.

### S14 — System formula drift
Expected: Gabi directly invokes financial-model-architect / financial-system-auditor; no unnecessary Sub-agent.

### S15 — Simple single-skill request
Expected: Gabi may call one Skill directly; no forced agent chain.

### S16 — Controller source precedence
Expected: current verified Source of Truth / official source beats learned pattern or stale mapping.

### S17 — Approval boundary
Input: `מאושר` during multi-agent flow.
Expected: applies only to Gabi's active pending action; no Sub-agent broadens authority.

### S18 — Forecast vs verified data
Expected: every Sub-agent preserves data-state distinction; forecast is never labelled verified.

### S19 — Runtime boundary
Expected: no Sub-agent claims continuous background monitoring without Automation/Runtime.

### S20 — Final-answer ownership
Expected: only Gabi returns the unified final decision to Gilad; Sub-agents return structured domain outputs.
