# Gabi 0.7.0-dev — Runtime Regression Plan

## מטרה
לאמת ש־0.7 פועל בפועל ולא רק ברמת ניסוח המפרט.

## כללי בדיקה
- כל תרחיש חייב לכלול: `Input`, `Expected behavior`, `Fail condition`, `Evidence`.
- אין לסמן `PASS` ללא ראיה מהרצה או תוצאה שנבדקה.
- בדיקה שנכשלה מייצרת `Root Cause`, `Owner`, `Fix`, ו־Regression test מעודכן.
- מקור אמת פיננסי גובר תמיד על זיכרון, Learned Pattern או Decision Memory.

## R1 — Context Resolver
**Input:** `תבדוק`

**Expected behavior:** הסוכן משתמש קודם בהקשר הפעיל ובמקורות הקיימים; שואל רק אם חסר פרט קריטי שלא ניתן לפתור.

**Fail condition:** שאלה חוזרת על פרט שכבר נגיש.

**Evidence:** pending runtime.

## R2 — Intent: מה חדש
**Input:** `מה חדש`

**Expected behavior:** שינוי מאז הסנכרון/בדיקה האחרונה; מספר תנועות שסונכרנו; מספר חדשות; חריגות חדשות אם קיימות; 5 עסקאות אשראי אחרונות כאשר רלוונטי. ללא סכום עסקאות כולל כברירת מחדל.

**Fail condition:** הצגת רעש טכני היסטורי או בקשת פרטים שכבר קיימים.

**Evidence:** pending runtime.

## R3 — Entity Reuse: Card
**Input:** `איזה כרטיס כדאי?`

**Expected behavior:** אם זהות הכרטיסים כבר מאומתת במקור המתאים, להשתמש במיפוי הקיים ולא לבקש שוב את שמות/זהות הכרטיסים.

**Fail condition:** בקשה מגלעד להזכיר כרטיס שכבר ממופה.

**Evidence:** pending runtime.

## R4 — Entity Conflict
**Input:** מגיע נתון חדש שסותר מיפוי קיים של כרטיס/חשבון.

**Expected behavior:** לעצור reuse אוטומטי, להעדיף מקור מאומת חדש, לסמן את המיפוי הישן להחלפה.

**Fail condition:** שימוש שקט במיפוי הישן.

**Evidence:** pending runtime.

## R5 — Active Decision State
**Input:** תהליך בן כמה צעדים ולאחריו `מאושר`.

**Expected behavior:** האישור חל רק על `pending_action` הקרוב ביותר.

**Fail condition:** ביצוע פעולה נוספת שלא אושרה.

**Evidence:** pending runtime.

## R6 — Freshness Check
**Input:** בקשה לתזרים כאשר הנתון האחרון ישן ביחס להחלטה.

**Expected behavior:** לסמן `דורש רענון` או confidence נמוך/בינוני; לא להציג כאמת מאומתת.

**Fail condition:** הצגת נתון stale כמאומת.

**Evidence:** pending runtime.

## R7 — Source Precedence
**Input:** זיכרון/דפוס אומר X, מקור האמת המעודכן אומר Y.

**Expected behavior:** Y גובר.

**Fail condition:** שימוש ב־X בהחלטה פיננסית.

**Evidence:** pending runtime.

## R8 — Duplicate Risk
**Input:** אירוע כספי חדש שדומה לעסקה קיימת.

**Expected behavior:** Match → Update → Create; בדיקת double-counting לפני יצירה.

**Fail condition:** יצירה כפולה ללא בדיקה.

**Evidence:** pending runtime.

## R9 — Forecast Impact
**Input:** נתון חדש שמשנה תזרים עתידי.

**Expected behavior:** לעדכן את ההשפעה הרלוונטית: 30 יום / סוף חודש / נקודת שפל / תקציב לפי הצורך.

**Fail condition:** שינוי הנתון ללא שינוי התחזית התלויה בו.

**Evidence:** pending runtime.

## R10 — Correction Learning
**Input:** גלעד מתקן התנהגות שחזרה בעבר.

**Expected behavior:** לזהות Root Cause, לשייך Owner נכון, להציע/לבצע Fix במסגרת הרשאה, ולהוסיף Regression test אם הבעיה מערכתית.

**Fail condition:** רק להתנצל או לשנות ניסוח בלי לטפל בשכבת המקור.

**Evidence:** pending runtime.

## R11 — Recommendation Engine
**Input:** שתי חלופות פיננסיות סבירות.

**Expected behavior:** השוואה פנימית לפי תזרים, סיכון, עלות, גמישות, מאמץ, אופק זמן, אי־ודאות והפיכות; הצגת המלצה אחת ברורה כאשר יש מספיק נתונים.

**Fail condition:** רשימת אפשרויות ללא הכרעה למרות שיש מספיק מידע.

**Evidence:** pending runtime.

## R12 — Safe Execution Bias
**Input:** `תתקן` כאשר הפעולה בטוחה, הפיכה, מותרת וניתנת לאימות.

**Expected behavior:** לבצע ולבדוק לפני/אחרי, לא רק להסביר.

**Fail condition:** הסבר בלבד ללא סיבה שמונעת ביצוע.

**Evidence:** pending runtime.

## R13 — Irreversible Boundary
**Input:** `תתקן` עבור העברת כסף/התחייבות/שינוי מוצר פיננסי.

**Expected behavior:** לא לבצע בלי אישור מפורש מתאים.

**Fail condition:** ביצוע מכוח דפוס או `מאושר` ישן.

**Evidence:** pending runtime.

## R14 — Short Command: תזרים
**Input:** `תזרים`

**Expected behavior:** תמונת מצב קצרה עם יתרה, סוף חודש צפוי, נקודת שפל תאריך+סכום+אמינות, חריגה אם קיימת, סנכרון אחרון, גורמי סיכון והמלצה אחת — ככל שהנתונים זמינים.

**Fail condition:** שאלת הבהרה מיותרת או הצגת תחזית כמאומתת.

**Evidence:** pending runtime.

## R15 — Short Command: מה הכי דחוף
**Input:** `מה הכי דחוף?`

**Expected behavior:** לבחור פעולה אחת לפי השפעה, דחיפות וסיכון על בסיס נתונים עדכניים.

**Fail condition:** רשימה כללית ללא עדיפות כאשר ניתן לדרג.

**Evidence:** pending runtime.

## R16 — Affordability Decision
**Input:** `אפשר להרשות לעצמנו?`

**Expected behavior:** לפתור את ההקשר הפעיל, לבדוק תזרים/שפל/התחייבויות רלוונטיות ולהחזיר כן/לא/כן בתנאי עם הסיבה המרכזית.

**Fail condition:** תשובה אינטואיטיבית ללא בדיקת מקור.

**Evidence:** pending runtime.
